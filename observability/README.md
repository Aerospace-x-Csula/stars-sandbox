## Purpose of the Observability folder 
This folder contains the OpenObserve and Telemetry collection configurations and documentation files. Includes guides in how to install and configure OpenObserve and Minikube Kubernetes clusters used for the STARS Project.

## Current OpenObserve Components
### OpenObserve Standalone: 
- OpenObserve Standalone is installed from the ```openobserve/openobserve-standalone``` Helm chart, under the release name ```openobserve```, in the ```stars``` namespace of the local Minikube cluster. It stores logs and serves the OpenObserve web interface. To reach the UI, forward ```port 5080``` to the openobserve-openobserve-standalone service and open ```localhost:5080``` in a browser. Sign in with the credentials from your own ```values.local.yaml```, which is created locally and never committed to git.

### OpenObserve Collector: 
- The ```OpenObserve Collector``` runs in the local Minikube Kubernetes cluster. It reads Kubernetes and container telemetry and forwards it to the OpenObserve instance running in the ```stars``` namespace. It is installed as the Helm release o2c in the ```openobserve-collector``` namespace and deploys two main components: an ```Agent Collector```, which reads telemetry from Kubernetes nodes and containers, and a ```Gateway Collector```, which receives that telemetry and sends it to OpenObserve.

## What is values.example.yaml used for?
The purpose of this file is to serve as a guide in how to create your private OpenObserve credentials where you will need to copy the contents inside of ```values.example.yaml``` and paste into a new file named ```values.local.yaml``` where you will input your OpenObserve Email and Password in order to access and view the Open Observe web user interface. This file will remain private and will not be pushed to git. 

## What is observability/o2c-values.yaml used for?
It serves as a template to create a new local private file ```o2c-values.local.yaml``` which will house access keys generated by OpenObserve. This file will remain private and will not be pushed to git. 

## How are local/private credentials handled? 

Local files such as ```values.local.yaml``` and  ```o2c-values.local.yaml``` remain private and on your local machine. It is important to keep these files from being committed to git. To make sure that these local file won't be committed and pushed make sure to check ```.gitignore``` to see if ```values.local.yaml``` or ```o2c-values.local.yaml``` is included in the file. 

Before committing you can check that git is ignoring these files by running
```
git status
```

```values.local.yaml``` or ```o2c-values.local.yaml``` should **not** appear as a file waiting to be committed. 


## How to Verify if OpenObserve is running
Verify that Minkube is running: 
``` 
minikube status
```
If it is stopped:
```
minikube start
```

Verify that OpenObserve is running:

```
kubectl get pods -n stars
```

The OpenObserve pod should show:
```
READY   STATUS
1/1     Running
```
Verify the OpenObserve service:
```
kubectl get services -n stars
```
The service should be:
```
openobserve-openobserve-standalone
```


## How to stop/remove OpenObserve where applicable: 

To stop Minikube & OpenObserve without deleting the cluster: 
```
minikube stop
```
This keeps the Kubernetes cluster and OpenObserve installation saved locally.

To Uninstall OpenObserve: 
- Use this if you want to remove the Helm release:
  ```
  helm uninstall openobserve -n stars
  ```
- To completely delete the local Minikube cluster:
  ```
  minikube delete
  ```
