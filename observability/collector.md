# OpenObserve Collector Installation (STARS)

This guide installs and configures the **OpenObserve Collector** in the local **Minikube Kubernetes cluster** used by the STARS project.

The collector reads Kubernetes/container telemetry and forwards it to the OpenObserve instance running in the `stars` namespace.

This guide assumes that OpenObserve has already been installed by following `install.md`.

---

## Prerequisites

Make sure you already have:

- Docker / Docker Desktop
- Minikube
- kubectl
- Helm
- OpenObserve installed and running in the `stars` namespace
- Access to the OpenObserve web UI
- A local copy of the STARS repository
- A log generator installed from /apps/log-generator/README guide.

Verify that Minikube is running:

```bash
minikube status
```

If it is stopped:

```bash
minikube start
```

Verify OpenObserve:

```bash
kubectl get pods -n stars
```

The OpenObserve pod should show:

```text
READY   STATUS
1/1     Running
```

Verify the OpenObserve service:

```bash
kubectl get services -n stars
```

With the STARS installation used in this project, the service should be:

```text
openobserve-openobserve-standalone
```

## 1. Open the OpenObserve Web UI

Forward local port `5080` to OpenObserve:

```bash
kubectl --namespace stars port-forward svc/openobserve-openobserve-standalone 5080:5080
```

Keep this terminal running.

Open a browser and go to:

```text
http://localhost:5080
```

Log in using the credentials created during `install.md`.

---

## 2. Get the Collector Access Key

In OpenObserve, go to:

```text
Data Sources -> Kubernetes
```

Enter a cluster name such as:

```text
stars-cluster
```

Select:

```text
Internal Endpoint
```

Open:

```text
Advanced Installation (Manual Steps)
```

OpenObserve will display an access key and installation settings for the collector.

Use the eyeball button to see your access key. The access key is after the "BASIC" word.

### Important

Do **not** commit the real access key to GitHub.

Do not paste the access key into documentation, issues, screenshots, or chat messages.

The access key will be used only in your private local configuration file.

---

## 3. Create the Collector Configuration Files

The repository should contain a safe template:

```text
observability/o2c-values.yaml
```

Example:

```yaml
k8sCluster: stars-cluster

exporters:
  otlphttp/openobserve:
    endpoint: http://openobserve-openobserve-standalone.stars.svc.cluster.local:5080/api/default
    headers:
      Authorization: "Basic REPLACE_ME"

  otlphttp/openobserve_k8s_events:
    endpoint: http://openobserve-openobserve-standalone.stars.svc.cluster.local:5080/api/default
    headers:
      Authorization: "Basic REPLACE_ME"
```

Create a private local copy:

```text
observability/o2c-values.local.yaml
```

Replace `REPLACE_ME` with the real access key generated by OpenObserve:

```yaml
k8sCluster: stars-cluster

exporters:
  otlphttp/openobserve:
    endpoint: http://openobserve-openobserve-standalone.stars.svc.cluster.local:5080/api/default
    headers:
      Authorization: "Basic YOUR_REAL_ACCESS_KEY"

  otlphttp/openobserve_k8s_events:
    endpoint: http://openobserve-openobserve-standalone.stars.svc.cluster.local:5080/api/default
    headers:
      Authorization: "Basic YOUR_REAL_ACCESS_KEY"
```

### Why this endpoint is used

DO **NOT** USE:

```text
http://localhost:5080
```

inside the collector configuration.

The collector runs inside Kubernetes. From inside the collector pod, `localhost` means the collector pod itself, not OpenObserve.

The collector communicates with OpenObserve through the Kubernetes internal service:

```text
http://openobserve-openobserve-standalone.stars.svc.cluster.local:5080
```

The full OTLP HTTP endpoint used by the exporter is:

```text
http://openobserve-openobserve-standalone.stars.svc.cluster.local:5080/api/default
```

## 4. Keep the Private Collector File Out of Git

Make sure the repository `.gitignore` contains:

```gitignore
observability/o2c-values.local.yaml
```

Check:

```bash
git status
```

`o2c-values.local.yaml` should not appear as a file waiting to be committed.

Only the safe template `o2c-values.yaml` should be committed.

## 5. Install the Collector Prerequisites

OpenObserve's Kubernetes collector setup uses supporting Kubernetes components such as:

- cert-manager
- Prometheus Operator CRDs
- OpenTelemetry Operator

Go to the OpenObserve web UI:

```bash
kubectl --namespace stars port-forward svc/openobserve-openobserve-standalone 5080:5080
```

Go to:

```text
Data Sources -> Kubernetes -> Advanced Installation (Manual Steps)
```

The Advanced Installation (Manual Steps) should be in blue text.

Run the prerequisite commands shown there **in order**.

The first line should look like this.

```text
# 1 — cert-manager (the OpenTelemetry operator's webhook depends on it)
```

Mac/Linux can run the commands with the backslash \ just fine.

Windows users need to copy and paste each command before the backslashes and paste the next part of the line.
Think of the back slashes \ as "continue this command on the next line".

These commands may change as OpenObserve updates its collector installation, so use the commands generated by the OpenObserve version you are running.

Wait for cert-manager to become available when instructed by OpenObserve.

You can check installed pods across namespaces with:

```bash
kubectl get pods -A
```

Run all commands until you reach a command starting with this:

```bash
helm --namespace openobserve-collector
```

All the --set need to ran in one command together.

There should be a part that looks like:

```bash
--set exporters.'otlphttp/openobserve'.endpoint=http://localhost:5080/api/default
```

The endpoint is wrong for our cluster. Change the endpoint to

```bash
http://openobserve-openobserve-standalone.stars.svc.cluster.local:5080/api/default
```

Your full line of that command should look like this:

```bash
--set exporters.'otlphttp/openobserve'.endpoint=http://openobserve-openobserve-standalone.stars.svc.cluster.local:5080/api/default
```

You will need to change the endpoint twice since the endpoint shows up twice.

Make sure you to use your access key when running it in your terminal/powershell.


## 7. Create the Collector Namespace

Create the namespace used by the collector:

```bash
kubectl create namespace openobserve-collector
```

If Kubernetes reports:

```text
AlreadyExists
```

that is okay.

Verify it:

```bash
kubectl get namespaces
```

## 8. Install the OpenObserve Collector

If you are in the root of the STARS repository, run:

```bash
helm upgrade --install o2c openobserve/openobserve-collector --namespace openobserve-collector -f observability/o2c-values.local.yaml
```

What this command means:

- `upgrade --install` creates the collector if it does not exist or updates it if it already exists.
- `o2c` is the Helm release name.
- `openobserve/openobserve-collector` is the collector Helm chart.
- `--namespace openobserve-collector` installs the collector into its own namespace.
- `-f o2c-values.local.yaml` loads the private local collector configuration.

A successful install should include:

```text
NAME: o2c
NAMESPACE: openobserve-collector
STATUS: deployed
```

## 9. Verify the Collector Pods

Check the collector namespace:

```bash
kubectl get pods -n openobserve-collector
```

You should see two collector components similar to:

```text
o2c-openobserve-collector-agent-collector-xxxxx
o2c-openobserve-collector-gateway-collector-0
```

Both should eventually show:

```text
READY   STATUS    RESTARTS
1/1     Running   0
```

The two main components are:

```text
Agent Collector
  -> reads telemetry from Kubernetes nodes and containers

Gateway Collector
  -> receives collected telemetry and sends it to OpenObserve
```

```bash
kubectl get pods -n openobserve-collector
```

```bash
kubectl logs -n openobserve-collector o2c-openobserve-collector-gateway-collector-0
```

### Agent Collector

Use the current agent pod name:

```bash
kubectl logs -n openobserve-collector <agent-collector-pod-name>
```

For example:

```bash
kubectl logs -n openobserve-collector o2c-openobserve-collector-agent-collector-xxxxx
```

## 12. Verify That Exporting Is Working

On Windows PowerShell, check for exporter failures:

```powershell
kubectl logs -n openobserve-collector o2c-openobserve-collector-gateway-collector-0 | Select-String "Exporting failed"
```

Mac/Linux can use this for exporter failures:

```bash
kubectl logs -n openobserve-collector o2c-openobserve-collector-gateway-collector-0 | grep "Exporting failed"
```

If the command returns nothing, there are currently no matching exporter failure messages in the gateway logs.

You can also check for common connection/authentication problems:

```powershell
kubectl logs -n openobserve-collector o2c-openobserve-collector-gateway-collector-0 | Select-String "localhost|Unauthorized|v1/logs"
```

Mac/Linux can use:

```bash
kubectl logs -n openobserve-collector o2c-openobserve-collector-gateway-collector-0 | grep -E "localhost|Unauthorized|v1/logs"
```

## 13. Find the Logs in OpenObserve

Open the OpenObserve UI.

If needed, start the port forward again:

```bash
kubectl --namespace stars port-forward svc/openobserve-openobserve-standalone 5080:5080
```

Go to:

```text
Logs
```

Select the log stream:

```text
default
```

The `k8s_events` stream contains Kubernetes event information. The generated application/container logs are available in the `default` stream in this setup.

Set the time range to something recent, such as:

```text
Past 15 Minutes
```

Then Run the Query.

Search for:

```text
STARS heartbeat
```

or:

```text
log-generator
```

A successful result should contain something similar to:

```text
level=INFO service=log-generator message="STARS heartbeat" count=1135
```

This confirms that the full log pipeline is working.

## 14. Telemetry Flow

The working STARS logging path is:

```text
log-generator pod
      |
      | stdout
      v
Kubernetes container logs
      |
      v
OpenObserve Agent Collector
      |
      v
OpenObserve Gateway Collector
      |
      | OTLP HTTP
      v
OpenObserve service
      |
      v
OpenObserve "default" log stream
      |
      v
Search / Dashboards
```

## Troubleshooting

### Collector tries to connect to `localhost:5080`

Example error:

```text
Post "http://localhost:5080/api/default/v1/logs":
dial tcp [::1]:5080: connect: connection refused
```

Cause:

```text
localhost
```

inside the collector pod refers to the collector itself.

Fix the endpoints in `o2c-values.local.yaml`:

```yaml
endpoint: http://openobserve-openobserve-standalone.stars.svc.cluster.local:5080/api/default
```

Then update the Helm release:

```bash
helm upgrade o2c openobserve/openobserve-collector \
  --namespace openobserve-collector \
  -f o2c-values.local.yaml
```

---

### `namespace "openobserve-collector" already exists`

This is not an error that requires fixing.

The namespace was already created.

Continue with the collector installation.

---

### Collector pod not found in namespace `stars`

The collector is installed in:

```text
openobserve-collector
```

not:

```text
stars
```

Correct:

```bash
kubectl logs -n openobserve-collector <collector-pod-name>
```

Incorrect:

```bash
kubectl logs -n stars <collector-pod-name>
```

The `stars` namespace contains the STARS workload and OpenObserve installation.

---

### Prometheus `10257` or `10259` warnings

In Minikube, the collector may show warnings similar to:

```text
Failed to scrape Prometheus endpoint
192.168.x.x:10257/metrics
connection refused
```

or:

```text
Failed to scrape Prometheus endpoint
192.168.x.x:10259/metrics
connection refused
```

These warnings can come from attempts to scrape Minikube control-plane metrics such as the Kubernetes controller manager or scheduler.

They do not automatically mean that container log ingestion is broken.

Verify logs separately by:

1. Confirming the collector pods are `Running`.
2. Checking that there are no `Exporting failed` messages for `/v1/logs`.
3. Searching the OpenObserve `default` stream for `STARS heartbeat`.

---

### `401 Unauthorized`

If the collector reports an authorization error:

```text
401 Unauthorized
```

check the access key in:

```text
o2c-values.local.yaml
```

Make sure the header has this format:

```yaml
Authorization: "Basic YOUR_ACCESS_KEY"
```

Do not commit the real access key.

---

### Logs do not appear in OpenObserve

Check each part of the pipeline.

First, verify the log generator:

```bash
kubectl get pods -n stars
```

Then:

```bash
kubectl logs -n stars <log-generator-pod-name>
```

Next, verify the collector:

```bash
kubectl get pods -n openobserve-collector
```

Then check the gateway for export failures:

```powershell
kubectl logs -n openobserve-collector o2c-openobserve-collector-gateway-collector-0 | Select-String "Exporting failed"
```

Finally, in OpenObserve:

```text
Logs -> default
```

Set a recent time range and search for:

```text
STARS heartbeat
```

## Stopping Work for the Day

Stop Minikube without deleting the cluster:

```bash
minikube stop
```

The collector and OpenObserve installations remain saved in the Minikube cluster.

The next time you work:

```bash
minikube start
```

Verify OpenObserve:

```bash
kubectl get pods -n stars
```

Verify the collector:

```bash
kubectl get pods -n openobserve-collector
```

Restart the OpenObserve port forward:

```bash
kubectl --namespace stars port-forward svc/openobserve-openobserve-standalone 5080:5080
```

---

## Uninstalling the Collector

Only use this if you intentionally want to remove the collector Helm release:

```bash
helm uninstall o2c -n openobserve-collector
```

To remove the collector namespace afterward:

```bash
kubectl delete namespace openobserve-collector
```

Normally, do not uninstall the collector when you are simply finished working for the day. Use:

```bash
minikube stop
```

instead.

---

## Collector Verification Checklist

Before considering the collector setup complete, verify:

- OpenObserve is running in the `stars` namespace.
- The `openobserve-openobserve-standalone` service exists.
- `o2c-values.local.yaml` contains the private access key.
- `o2c-values.local.yaml` is ignored by Git.
- The collector Helm release is deployed.
- The agent collector is `1/1 Running`.
- The gateway collector is `1/1 Running`.
- The log generator produces `STARS heartbeat` messages.
- The gateway is no longer reporting OpenObserve export failures.
- The OpenObserve `default` stream contains `STARS heartbeat` logs.

When all of these are true, the baseline STARS Kubernetes log pipeline is working.
